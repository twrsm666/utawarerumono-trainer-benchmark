# 《传颂之物：虚伪的假面》单机修改器

针对 PC 版（32 位 PE32、Aquaplus UT2 引擎、无反作弊）做的本地修改器。
依据 `TRAINER-二代修改器制作说明书.md` 的结构分析实现，**不预设任何未经验证的内存偏移**——由你在游戏里搜值、筛选、写入，因此不会因游戏搬迁、更新、ASLR 而失效。

Python 3 标准库实现，零第三方依赖，不联网、不上传任何数据。

---

## ⚠️ 重要更正：上一版「人物属性」页数值是错的

上一版把 `UnitData.bin` 的**静态模板参数**（哈克 `300 / 600 / 100 / 60 / 32 / 110 / 105 …`）当成了角色当前属性，与游戏里 Lv3 哈克显示的「体力 66/66、攻击力 15、防御力 18、敏捷度 120、气力 70」完全不一致。

原因：`UnitData.bin` 是数据表模板；界面上那组属性很可能由等级 / 装备 / 成长**动态计算**，并不以 `66 / 15 / 18 / 120 / 70` 的形式成组存放。已按 u8 / u16 / u32 / float 做过全内存聚类、连续模式、跨类型组合与邻近数据表区域排查，命中的都是查表、纹理、地图格子与 UI 数值缓存（例如 `0x17591C0` 是每隔 0x40 递增的 `66.0, 67.0, 68.0…`），**不是角色对象**。

因此本版做了两件事：
- 原页面降级为 **「数据表模板」**，顶部加醒目警示，明确「数值与游戏内显示不一致」，仅供研究数据表结构。
- 默认首页改为 **「实时角色」**，用数值变化定位真实运行时地址。

## 实时角色页（推荐，默认首页）

游戏的显示值无法靠静态特征可靠定位，唯一稳妥的办法是**让数值变化，用变化来筛选**（Cheat Engine 的经典流程，这里做成两步引导）：

1. 在「当前可见数值」填游戏里真实看到的数（例如体力 `66`），类型选「自动（2/4 字节整数 + 浮点）」，点 **① 扫描当前值**。实测 1GB 内存约 3.5 秒，会得到约 25 万个候选——这是正常的。
2. 回游戏让这个数变化（受一次攻击、切换角色、用掉气力等），在「变化后的新值」填新数字，点 **② 按新值筛选**；也可先点「只保留变过的」。重复 1~2 轮，通常收敛到个位数地址。
3. 点选一个候选地址 → 工具把它周围 ±256 字节解析成一张可编辑的**角色卡**，字段可直接改（支持 u16 / u32 / f32）。

**字段标记是中性的**：工具只把数值碰巧等于 `66 / 15 / 18 / 120 / 70` 的字段标成「= 界面数值 N」，**不会声称它就是体力或攻击力**——这些小整数在 1GB 内存里大量出现，自动命名必然误导（`1 / 3 / 4` 更常见，已排除）。请改一个明显的值（例如 999）进游戏看界面哪里变化，再确认字段含义。工具不伪造无法验证的结论。

> 这是目前唯一能保证「改到的数值与游戏界面一致」的方式。若你希望完全零交互，需要进一步逆向 `CBattle` / `CStatusTask` 的对象布局（交接说明书 §12 开放问题②），本工具没有伪造这部分结论。

## 一、通用数值扫描：三步开始

1. 先启动游戏，进入能看到金钱 / BP / HP 的界面。
2. 双击 `启动修改器.bat`（或 `start.bat`），界面会自动在浏览器打开。
3. 「内存修改」页 → 刷新 → 选中 `Utawarerumono Mask of Deception.exe` → **附加进程** → 填入游戏里当前显示的数值 → **首次扫描**。

之后让数值变化（买件东西、打一场、升一级），用「再次扫描」反复筛选，结果收敛后写入或加入地址表锁定。详细流程见界面「使用指南」页。

> 若游戏以管理员权限启动，修改器也必须以管理员权限启动，否则 `OpenProcess` 会失败。

## 二、功能

### 内存修改（主路线）
- 自动识别游戏进程；按进程名匹配，不依赖会随语言变化的窗口标题。
- 全内存区域扫描（`VirtualQueryEx` 枚举已提交可读区，逐块 `ReadProcessMemory`），覆盖引擎自研分配器 `Kernel::CAllocator` 的堆。
- 类型：1/2/4/8 字节有符号与无符号整数、float、double；可选按类型宽度对齐扫描。
- 再次扫描模式：等于 / 不等于 / 大于 / 小于 / 已变化 / 未变化 / 增大 / 减小 / 增加指定量 / 减少指定量 / 介于两值之间。
- 结果分页展示：地址、当前值、首次值、**模块 RVA**（有值＝静态区，可跨重启复用；空白＝引擎堆，重启需重扫）。
- 单地址写入、地址表、数值锁定（0.12 秒轮询写回）、`Alt+1~9` 快捷切换锁定。
- 地址表保存为 `address_table.json`，重新附加时按「模块基址 + RVA」自动还原，对抗 ASLR。

### 存档编辑（备用路线）
- 自动探测 `Documents\AQUAPLUS\受讚頌者 虛偽的假面\`，也支持手动指定目录。
- 解析并展示文件头 A / B / C / L / 版本 / 类型标签，实时校验 A 是否有效。
- 按已知数值在存档里搜索偏移（u32 / i32 / u16 / i16 / float），点选即加入编辑列表。
- 批量写入 + **自动重算 A 校验** + 自动 `.bak-时间戳` 备份 + 一键还原 + 十六进制查看。
- B 字段提供「保留原值 / 清零 / 自定义」三种策略，界面明确标注其风险（见下节）。

## 三、本次逆向的新结论（相对交接说明书）

| 项 | 结论 |
| --- | --- |
| **A 校验（0x00）** | **已完全破解**：`A = Σ(save[0x10:]) + (len(save) - 16)`，mod 2³²。本机两代游戏共 **27/27** 个 `.DAT` 全部吻合。可用 `python verify_checksum.py` 独立复现。 |
| **C 字段（0x0C）** | **不是校验和**。常见 0 或 `0xBB80`(48000)，是游戏数据/标志。交接说明书 §4.1 把它列为「校验 C」属误判。 |
| **B 字段（0x04）** | **未破解**。已排除：标准/自定义初值与异或输出的 CRC32（含 exe 内标准表 file `0x4CE890`）、CRC32C、FNV-1/FNV-1a、Adler-32、djb2、sdbm、Jenkins、加权和、MD5/SHA/Blake2 切片，以及「任意上述 hash ⊕ 或 + 固定常量」；穷举过 0x00–0x30 全部起止范围组合。 |
| **exe 内 FNV 函数** | file `0xFBA65`（va ≈ `0xFC665`）是一个**只处理 4 字节**的 FNV-1a（`mov edx,811C9DC5` / `xor eax,edx` / `imul edx,eax,01000193` / `cmp ecx,4`），用于哈希 `"GAME"`、`"1.00"` 这类短标签，**不是存档校验**。 |
| **CRC32 表** | 标准反射表位于 file `0x4CE890`，另有副本 `0x4E6340`；B 与任何 CRC32 变体都不匹配。 |
| **角色数据表（新）** | `CHN/DataBase.sdat → UnitData.bin`（399126 B）：`@0` count=307，属性块在 `0xD8 + i×0x208`，每块 12 个 u16（哈克 = `300 600 100 60 32 110 105 150 150 200 1536 1024`）。共 187 个带属性的单位。 |
| **角色名表（新）** | `DataBase2.sdat → UnitTextData.bin`（10912 B）：307 个 u32 指向 UTF-8 名字串，每 3 槽 = JPN\|KOR\|ZH 一组；多数条目只有日文槽，从完整组学出「日文→繁中」映射后可为全部 307 个单位配上中文名。 |
| **内存重定位（新）** | 游戏把 UnitData.bin 整表载入内存，并把文件内所有 u32 偏移改成「表基址 + 文件偏移」（实测 `0x017DA1AC = base + 0x19BEC`），属性数值保持原样。特征码 `UnitData[0xD0:0x100]` 在 ~1GB 内存中唯一命中 → `base = hit − 0xD0`（本机 `0x017C05C0`）；属性块与文件 9/9 逐字段一致，重开游戏自动重新定位。 |
| **sdat 容器解析（新）** | 纯 Python 实现见 `unit_table.py`：magic `Filename`，`@12` 索引尾指针，附近 8 字节找 `Pack`，`count=u32(n0+16)`，`namesAt=16+4×count`，成员 `(off,size)` 对从 `n0+20` 起。 |
| **运行时角色状态（未解）** | 游戏 UI 的 `66/15/18/120/70` 未能在内存中成组定位。已排除：u8/u16/u32/f32 各类型全内存聚类、连续字节模式、数据表邻近区域、`float 66/66`（`0x17591C0` 实为每 0x40 递增的查表）。推测显示值由基础值动态计算。对应交接说明书 §12 开放问题②，需动态调试 `CBattle` / `CStatusTask` 对象布局。 |

存档编辑因此处于「**A 可重算、B 待验证**」状态。工具默认保留 B 原值，请先用试验存档验证游戏是否校验 B：若读档提示损坏，一键还原备份，改用内存路线。这是说明书 §12 开放问题①的当前进度，也是继续逆向的入口（下一步应动态调试 `CSave` / `CSaveLoadBase` 的序列化函数）。

## 四、边界与纪律

- 仅做本机进程内存数值读写与本地存档文件编辑；**不注入 DLL、不 hook、不改 exe、不碰任何启动校验或 Steam 组件**，不会改动你做过的简体中文字形补丁（`font.tex`）。
- 改存档前必定自动备份；数值写入防越界（道具数量建议 ≤ 99）。
- 战斗对象每场重建，HP 类地址在战斗结束 / 读档 / 重开后失效属正常现象，需重新扫描。
- 仅限个人单机离线使用；不要附带任何原游戏文件分发。

```
├── 启动修改器.bat       一键启动（内容全 ASCII，避免 cmd 编码问题）
├── start.bat            同上，纯英文名
├── utawa_trainer.py     后端：Win32 内存读写 + 本地 HTTP JSON API
├── unit_table.py        角色数据表解析 + 内存表自动定位 + 属性读写
├── web/index.html       前端：中文浅色主题 GUI（单文件，内联 CSS/JS）
├── verify_checksum.py   独立复现 A 校验公式
├── address_table.json   运行时生成，地址表持久化
├── unit_config.json     运行时生成，字段名 / 角色自定义名
└── README.md            本文件
```

| 现象 | 处理 |
| --- | --- |
| 附加失败 / `OpenProcess` 错误 | 游戏若以管理员运行，右键 bat 选「以管理员身份运行」。 |
| 刷新进程列表为空 | 确认游戏已启动；进程名是带空格的 `Utawarerumono Mask of Deception.exe`。 |
| 首次扫描 0 结果 | 换数值类型（先 4 字节，再 2 字节 / float）；关掉「对齐扫描」重试；确认填的是游戏里显示的准确值。 |
| 写入后数值被改回 | 该值由游戏逻辑每帧重算，改用地址表「锁定」。 |
| 重启游戏后地址失效 | 堆地址必然变化。优先使用结果表里带「模块 RVA」的地址，或重新走一遍扫描流程。 |
| 读档提示存档损坏 | 存档编辑页点「一键还原备份」，改走内存路线；或切换 B 策略再试。 |
| 端口被占用 | 后端自动从 18765 起递增探测，以控制台打印的地址为准。 |
| 人物页「识别失败」 | 工具从附加进程的 exe 路径推断游戏目录；若 exe 被移动或目录结构不同，在 `unit_table.py` 的 `UnitTable.load()` 传入正确目录，或确认 `Data/CHN/DataBase.sdat`、`Data/DataBase2.sdat` 存在。 |
| 人物属性改了没效果 | 改的是基础属性表，进战斗 / 重新编成 / 读档后才读取；战斗中已生成的单位对象需用「数值扫描」改实时值。也可勾选「锁定数值」。 |
| 角色名重复 | 同一角色的多个形态 / 等级变体在数据表里本来就是多条记录，用 `#编号` 区分；可在右侧详情里直接改名。 |
| 实时角色扫描后候选太多 | 25 万个属正常，必须让游戏里数值变化后再筛选。只点选地址不会自动识别角色，页面会提示「未确认为角色对象」。 |
| 角色卡里「= 界面数值 15」的字段改了没反应 | 这只是数值碰巧相同，不是该属性。继续筛选候选地址，或改用「数值扫描」页按类型的变化流程精确定位。 |

更正：数据表模板页的数值不是角色当前状态

上一版把 UnitData.bin 的静态模板参数（300 / 600 / 100 / 60…）当成角色属性，与游戏里 Lv3 哈克显示的「体力 66/66、攻击 15、防御 18、敏捷 120、气力 70」不一致。界面上那组数值很可能是按等级 / 装备 / 成长动态算出来的，并不成组存于内存；按 u8 / u16 / u32 / float 做全内存聚类、连续模式和邻近区域排查，命中的都是查表、纹理、地图格子和 UI 数值缓存，不是角色对象。

该页已降名为「数据表模板」并加警示，请勿当成当前角色状态。默认首页已改为「实时角色」。

实时角色页：改到与界面一致的数值

  1. 填游戏里真实可见的数字（如体力 66），类型选「自动」，点「① 扫描当前值」。1GB 内存约 3.5 秒，出现约 25 万个候选是正常的。
  2. 回游戏让这个数变化（受击、换人、消耗气力），填新数字点「② 按新值筛选」，或先点「只保留变过的」。重复 1~2 轮通常收敛到个位数地址。
  3. 点选候选地址，工具把周围 ±256 字节解析成一张角色卡，字段可直接改（u16 / u32 / f32 可切）。

字段标记是中性的：只把数值碰巧等于 66 / 15 / 18 / 120 / 70 的字段标成「= 界面数值 N」，不声称它就是该属性。这些小整数在 1GB 内存里大量出现，自动命名必然误导（1 / 3 / 4 已排除）。请改一个明显的值（如 999）进游戏看界面哪里变化，再确认字段含义。

数值扫描：改金钱

1启动与附加
先运行游戏，再运行本修改器（启动修改器.bat），界面会自动在浏览器打开。在「内存修改」页点「刷新」→ 选中 Utawarerumono Mask of Deception.exe → 点「附加进程」。状态栏变绿并显示模块基址即成功。
2首次扫描
进入游戏里能看到金钱的界面，记下准确数字。类型选「4 字节整数」，填入数字，点「首次扫描」。首次扫描会遍历全部可读内存区域，通常几秒。
3让数值变化，反复筛选
回游戏买/卖一件东西使金钱改变，在「再次扫描」里输入新金额、选「等于」，点再次扫描。重复 2~3 次，结果通常收敛到 1~5 个地址。
4写入 / 锁定
在结果行右侧输入目标值点「写入」，或点「加入」放进地址表并勾选「锁定」实现无限金钱。地址表保存在 address_table.json。

关于地址会变（ASLR 与引擎堆）

exe 带 DYNAMIC_BASE，且对象由自研分配器 Kernel::CAllocator 分配在引擎堆上，所以每次启动地址都会变。本工具的应对：

  • 扫描结果里的「模块 RVA」列：有值说明该地址落在主模块静态区，可按 模块基址 + RVA 跨重启复用；空白说明在堆上，重启后必须重新扫描。
  • 地址表自动记录 RVA，重新附加进程时会自动按新基址还原。堆地址条目则会保留原值，需手动重新定位。
  • 战斗对象每场战斗重建，HP 类地址在战斗结束 / 读档 / 重开后失效属正常现象，重新按流程扫描即可。

存档编辑路线（备用）

当内存路线卡住时可用存档编辑：改完读档即生效，不受 ASLR 影响。本工具会自动备份原档（.bak-时间戳）、重算已破解的 A 校验，并提供一键还原。

已知限制：头部 B 字段（0x04）算法未逆向，游戏是否校验它尚未实测。请务必用试验存档验证：改一个明显无关的数值 → 进游戏读档 → 若提示存档损坏，说明 B 参与校验，请用「一键还原」恢复，并改走内存路线。B 的三种策略可在界面里切换尝试。

定位数值建议用「差分法」：存两个不同进度的档，在存档编辑页用已知数值搜索偏移；也可以先在游戏中用内存扫描找到数值，再用该数值的字节模式在存档里搜对应偏移。

本次逆向新增结论（相对交接说明书）

  • A 校验已破解：A = Σ(save[0x10:]) + (len - 16)，27/27 个存档（含一代《给逝者的摇篮曲》与二代）全部吻合，两代格式同构。
  • C 不是校验和：0x0C 字段常见 0 或 0xBB80(48000)，是游戏数据 / 标志，说明书把它列为「校验 C」属误判。
  • exe 内 FNV 函数已定位：file 0xFBA65（va ≈ 0xFC665）是一个只处理 4 字节的 FNV-1a（哈希 "GAME"/"1.00" 这类短标签），并非存档校验。
  • CRC32 表：标准表位于 file 0x4CE890，另有副本 0x4E6340；B 不匹配任何 CRC32 起始范围/初值/异或组合，也不是 MD5/SHA/Adler/FNV 加常量偏移。
